# V2.1.0 UI/UX Audit and Construction Record

## Scope

V2.1.0 focuses on product experience, not new backend claims. The goal is to make the existing V2.0.0 runtime foundation easier to operate: clearer status hierarchy, better action feedback, less ambiguous empty state, and a Dashboard that behaves like an operator cockpit.

The UI/UX review used `ui-ux-pro-max` with a dense operations-control-panel profile:

- Balanced / modern visual variance.
- Standard, reduced-motion-safe micro-interactions.
- High-density dashboard spacing.
- Semantic state colors for ready, waiting, attention, blocked, and failed.
- Accessibility priorities: visible focus, non-color-only state labels, useful empty states, and touch-safe action targets.

## Current UX Findings

### Strengths

- V2.0.0 already has a tokenized visual system and reduced-motion tests.
- Navigation is grouped around Operations, Customers & Policy, and Evidence & Settings.
- Major runtime pages already expose evidence drawers, recovery context, and typed task feedback.
- The 4174 deployment path uses persistent SQLite state instead of a blank demo store.

### Remaining Problems

- The Dashboard still leaned toward a topology preview rather than a daily operations queue.
- Global mutation feedback looked like a generic banner and did not explain that runtime evidence remains authoritative.
- Empty states existed but were visually inconsistent across Nodes, Subscriptions, Forwarding, Tasks, and Audit.
- Several large pages still contain local hardcoded color fragments; the global token layer now overrides the most visible empty-state and feedback surfaces, but deeper cleanup remains for V2.2+.
- Customer-node, Subscription, and Forwarding workspaces still need deeper form and drawer simplification after this V2.1 cockpit layer.

## Implemented UI Changes

- Dashboard `Operator Triage` region:
  - `failed-tasks`
  - `runtime-changes`
  - `agent-coverage`
  - `node-health`
  - `forwarding`
  - `subscription-delivery`
- Triage rows include state labels, values, metadata, and direct actions where a real workspace path exists.
- Global mutation feedback now uses `data-task-mutation-feedback`, `aria-live`, status labels, message text, and an evidence hint.
- Shared empty states now use tokenized surfaces and dashed evidence framing while preserving compact `p-3` density.

## Not Completed in V2.1.0

- Full rewrite of the huge Nodes / Subscriptions / Forwarding pages.
- Form autosave, multi-step wizards, and unsaved-change protection across every drawer.
- Full screenshot regression suite across all viewports.
- Full replacement of local legacy color fragments inside deep page-specific components.

Those are better handled in V2.2+ as smaller, page-specific rounds.
